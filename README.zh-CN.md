# UPS 守护

通过 NUT 服务器监测 UPS，在负载超限时降低本机功耗，并在电池不足时按规则休眠的 Windows 托盘应用。

[English](README.md) · [下载版本](https://github.com/kylefu8/ups-guardian/releases) · [更新记录](CHANGELOG.md)

## 当前状态

当前为 **Windows 测试版**，在 Windows 11 x64 上验证了监测与界面。规则、恢复和更新使用模拟测试验证。实际限功耗、恢复及休眠需要在自己的电脑上安排受控测试，不能把模拟测试视作硬件兼容性保证。

macOS 留待下一阶段。本版已整理可复用的通讯、规则、语言资源和平台接口，但没有提供 Mac 程序，也不承诺 Mac 支持 Windows 式显卡瓦数限制或休眠。

## 使用

1. 从 Releases 下载 Windows 安装包或便携 ZIP。安装包适合按当前用户安装；使用 ZIP 时请解压到可写目录，运行 `UPSGuardian.exe`，并保留同目录的 `UPSGuardian.Updater.exe`。
2. 在「连接设置」点击「搜索局域网」，从结果中选择一台 UPS，再点击「确认并连接所选 UPS」。没有可读取的结果或尚未确认时，不开始监测，也不能启用保护。默认扫描 NUT 3493 端口，可调整扫描端口；服务器需允许本机执行只读 `LIST UPS` 和 `LIST VAR` 查询。
3. 确认成功后先只读监测，再到「保护策略」确认功率口径、阈值和本机限制。新配置按负载百分比设置阈值，不假设其他 UPS 的额定瓦数。
4. 确认硬件能力并验证限制与恢复后，以管理员身份打开，再手动启用自动保护。
5. 关闭窗口会收起到系统托盘。「暂停并恢复限制」停止自动动作；「退出」恢复本程序拥有的限制后结束进程。

程序会记住唯一确认目标，下次启动先验证同一目标，可读取才恢复监测；失败时回到发现页面，不会自动选择其他 UPS。每次启动后，自动保护都需要手动开启。旧配置的地址和保护参数会保留，但首次使用发现功能仍需确认目标。

## 安装方式

- **安装包：** 运行 `UPSGuardian-{version}-windows-x64-setup.exe`，按当前用户安装。默认目录为 `%LOCALAPPDATA%\Programs\UPS Guardian`；安装时可创建开始菜单项，也可选择创建桌面快捷方式。程序的 `data/` 会保留在安装目录中。
- **便携 ZIP：** 解压 `UPSGuardian-{version}-windows-x64.zip` 到任意可写目录后运行，两个 EXE 需要放在一起。适合自行选择目录或不需要快捷方式的情况。
- **升级：** 应用内更新下载并安装 ZIP。重新运行安装包并选择同一目录会保留 `data/`；安装到不同目录不会自动迁移旧目录的 `data/`。
- **卸载：** 卸载前请暂停保护、恢复程序拥有的限制，并从系统托盘退出。如果启用了登录自启，请先在应用内关闭并保存。检测到 `recovery.xml` 时，安装和卸载会被阻止，必须先完成恢复，避免遗留程序拥有的功耗限制。卸载程序会保留 `data/`，便于备份设置、事件和恢复记录，确认后再手动清理。

确认连接后，连接页收起搜索区；点击「更换 UPS」才重新展开，展开本身不会切换设备或发起搜索。保护页默认突出负载、电量和续航三个阈值；CPU/GPU 限制、恢复回差、单位及倒计时放在「高级设置」中，折叠不会改动参数。动作摘要始终显示实际限制和恢复条件。概览中的负载曲线可按需展开，后台继续保留最近的曲线数据。

发现优先扫描带网关的活动以太网/Wi-Fi IPv4 接口；没有此类接口时才使用其他活动以太网/Wi-Fi 接口。较大的网段只扫描本机所在 `/24`，最多 1024 个地址、16 个并发探测、30 秒总时限，可随时取消；实际范围会显示在界面上。未找到设备时，请检查范围、端口与 NUT 客户端白名单。IPv6 和跨网段发现暂不支持。

界面支持简体中文、英语、日语、韩语、法语、德语和西班牙语，切换语言不重启监测。「使用说明」「版本更新」「支持开发」均可从左侧一级菜单直接打开；使用说明详细介绍连接、阈值、权限、休眠、托盘操作与常见故障。

侧栏下方的地球图标可打开语言菜单，显示当前选择并支持跟随系统；旁边常驻显示当前版本，点击版本号可进入更新页面。

## 关键规则

- 超阈值持续 5 秒后降低本机功耗；回落到「阈值 − 回差」以下并持续 30 秒后恢复原设置。
- GPU 目标为 `0` 表示只限制 CPU。正值必须落在运行时检测范围内；不会提高用户已有的更严格限制。
- **只有电池供电时**，电量低于 50% 或续航低于 180 秒，才按默认的 5 秒确认与 20 秒倒计时准备休眠。
- 来电、条件解除、数据失效或手动暂停会取消待执行休眠。
- 休眠尽量保留 Windows 会话，不等于每个应用都保存了文件；计算任务仍需要自己的 checkpoint。
- UPS 总负载包括其上所有设备。没有实测瓦数时，仅在负载率和额定瓦数都存在的情况下估算；不能将其当作本机精确功率。

## 在线更新

在左侧「版本更新」中可检查 GitHub、下载并安装新版本。即使当前通过安装包安装，应用内更新仍使用 ZIP。执行应用内更新前，请先暂停保护并等待程序恢复它拥有的限制；更新程序会等待主程序退出，安装完成后自动重启。直接运行安装包或卸载程序时，请先恢复已有功耗限制并从系统托盘退出。更新程序会重新校验 SHA-256，只替换允许的发行文件；失败时回滚，本地 `data/` 不被覆盖。

版本号统一定义在 `version.json`。测试版可以发现预发布版本，稳定版忽略预发布版本。当前测试版尚无代码签名。

## 源码与构建

```powershell
.\build.ps1
.\test.ps1
.\package.ps1
```

构建产物在 `artifacts/windows-x64`；`artifacts/release` 默认包含便携 ZIP、Windows 安装包、`SHA256SUMS.txt` 和 `RELEASE_NOTES.md`。不传覆盖参数时，`package.ps1` 会下载固定版本 Inno Setup 6.7.3，校验 SHA-256 后以 portable 模式解压到项目的 `artifacts/tools`，不会查找或修改全局 Inno Setup。只有准备使用其他编译器时，才通过 `-InnoCompiler` 传入明确的 `ISCC.exe` 路径。`test-installer.ps1` 会在隔离沙箱中检查安装与卸载。模拟测试不会主动设置真实功耗或触发休眠。

`data/` 包含本次安装的设置、语言选择、事件和待恢复记录。同目录覆盖安装和 ZIP 更新会保留它；安装到不同目录不会自动导入；待恢复时安装和卸载会阻止继续；卸载也会保留。`data/`、收款码原图和本机日志不进入 Git 或源码发布。收款码作为可选发行构建资源提供，打赏不影响任何功能。

详见 [架构](docs/architecture.md)、[发布流程](docs/releasing.md) 和 [MIT 许可证](LICENSE)。
